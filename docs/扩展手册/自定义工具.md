# 扩展手册：自定义工具

`tool.NewFunc` / `tool.Typed` 覆盖了进程内函数的大多数场景（见 [tool 手册](../使用手册/tool.md)）。本篇讲需要**实现 `tool.Tool` 接口**的进阶场景：包装远程调用、包装外部 SDK、以及让自定义工具正确参与审批与恢复。

## 接口与可选能力

```go
// 必须实现
type Tool interface {
	Definition() Definition
	Execute(ctx context.Context, args map[string]any) (Result, error)
}

// 按需实现；审批与恢复有不同默认值
type ReadOnlyTool interface{ IsReadOnly() bool }          // 只读 → 默认免审批
type Sourced interface{ SourceID() string; SourceName() string } // 事件/审批里的来源标注
type RetryClassifier interface{ RetryPolicy() tool.RetryPolicy } // 恢复对账分级
```

未实现 ReadOnlyTool 时默认需要审批；但未实现 RetryClassifier 时恢复按 RetrySafe 处理。存在不可重复副作用时应显式声明恢复分级，不能依赖审批默认值防止恢复重试。

## 场景一：包装 HTTP 远程工具

要点：ctx 全程透传（超时/取消必须生效）、结果限制大小、区分两种失败。

```go
type httpTool struct {
	name  string
	url   string
	count atomic.Int64 // 实测执行次数，便于观测
}

func (t *httpTool) Definition() tool.Definition {
	return tool.Definition{Name: t.name, Description: "调用内部服务",
		Parameters: map[string]any{"type": "object",
			"properties": map[string]any{"q": map[string]any{"type": "string"}}}}
}

func (t *httpTool) Execute(ctx context.Context, args map[string]any) (tool.Result, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodPost, t.url, mustJSON(args))
	if err != nil {
		return tool.Result{}, err
	}
	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return tool.Result{}, err                    // 执行失败（网络层）
	}
	defer resp.Body.Close()
	body, err := io.ReadAll(io.LimitReader(resp.Body, 128<<10))
    if err != nil { return tool.Result{}, err }
	if resp.StatusCode >= 400 {
		return tool.Error(fmt.Sprintf("服务返回 %d: %s", resp.StatusCode, body)), nil // 业务失败回传模型
	}
	return tool.Text(string(body)), nil
}
```

## 场景二：包装现有 service（结构体注入依赖）

业务依赖可通过结构体或闭包注入。以下为应用相关片段，TicketService 与 schema 由应用定义：

```go
type assignTool struct{ svc *TicketService }

func (t *assignTool) Definition() tool.Definition { /* schema */ }
func (t *assignTool) Execute(ctx context.Context, args map[string]any) (tool.Result, error) {
    ticketID, ticketOK := args["ticket_id"].(string)
    assignee, assigneeOK := args["assignee"].(string)
    if !ticketOK || !assigneeOK { return tool.Error("ticket_id and assignee must be strings"), nil }
	if err := t.svc.AssignTicket(ctx, ticketID, assignee); err != nil {
		return tool.Result{}, err
	}
	return tool.Text("已指派"), nil
}
```

## 场景三：为写工具声明恢复分级

工具会在"已开始执行、结果未落库"时崩溃的窗口里被恢复对账处理。有不可重复副作用的工具**必须**声明 `NoRetry`，否则恢复时会被当作 `RetrySafe` 重新执行：

```go
type emailTool struct{ client *smtp.Client }

func (t *emailTool) RetryPolicy() tool.RetryPolicy { return tool.RetryPolicyNoRetry }
```

参见 [runtime 手册](../使用手册/runtime.md)的恢复对账一节：`NoRetry`/`NeedsVerify` 的调用在恢复运行中会被持续阻断并收到处置指引，；当前没有通用的解除阻断 API，核实外部状态及后续处置由应用实现。

## 场景四：参考实现——MCP adapter 怎么做的

把一套异构工具适配进本库，[`mcp/adapter.go`](../../mcp/adapter.go) 是最好的参照，它的模式值得抄：

1. **薄包装**：adapter 持有远程 client 与全名，`Execute` 内部转发 `CallTool`；
2. **来源透传**：实现 `Sourced`，把 `serverID/serverName` 带进事件与审批请求——前端能显示"该操作来自 filesystem 服务"；
3. **保守只读**：服务端 `readOnlyHint` 缺失时按不安全处理，而不是乐观放行；
4. **错误翻译**：远程调用的失败尽量转成 `tool.Error`（业务失败）回传模型，仅基础设施级故障返回 error。

## 命名与 schema 建议

- 工具名用小写下划线（`assign_ticket`），与模型训练分布一致；
- Description 写"何时该用我"，也写"何时该用别的工具"（mdk 的做法：区分相似工具的使用场景，显著减少误调用）；
- `required` 只放真正必需的参数；可选参数在 Description 里说明默认值；
- 参数越扁平越好——嵌套对象的部分模型处理得差。

## 测试

工具是纯接口，直接表驱动测试 `Execute`；放进 agent 全链路测时，用函数桩替代模型（参照 `runtime/resume_test.go` 的写法）——不需要真实模型服务。
