# 升级计划

版本节奏、API 兼容承诺、路线图与已知边界。原则：**克制扩张**——不为功能清单添砖，只为真实需求开门。

## 版本策略

| 阶段 | 主题 | 内容 |
|---|---|---|
| **v0.1.0**（下一个 tag） | 首个公开版本 | 现有能力冻结打包：llm/provider/factory、tool/message、agent、mcp、runtime（实验性）、rag（实验性）、storage；CI（ubuntu+windows, -race）；完整文档 |
| **v0.2.x** | 嵌入门面 | 最小 `Client` 门面（`NewClient`/`Start`/`GetRun`/`Wait`/`Cancel`/`Subscribe`/`Close`，见[架构设计 §19 阶段一](embedded-integration-design.md)）；`GetRun` 只读重访；迁移 ModelBox 验证；独立接入示例补全 |
| **v0.3.x** | 生产化 | 统一 Error 码体系（见[错误模型](扩展手册/错误模型.md)）；官方 Preset（SQLite 开箱、LocalOllama）；Preset 契约测试套件；迁移 mdk 收尾 |
| **v1.0** | API 冻结 | `tool` / `message` / `agent` 公共契约不再破坏性变更；次版本只增不改 |

**节奏承诺**：不设固定日期，按里程碑发布；每个 tag 附迁移说明（Breaking changes 逐条列出 + sed 级修改指引）。

## API 稳定性承诺

| 层级 | 承诺 |
|---|---|
| `tool` / `message` | 已稳定。结构体字段与 JSON tag 是**持久化契约**，改动即破坏存储兼容——只在主版本动 |
| `llm.Provider` / `agent.Config` / `agent.Event` | 只增不改：新字段可选扩展，零值语义不变 |
| `runtime` / `rag` / `storage` | **实验性**：语义持续打磨（恢复对账、Pipeline），接口可能小调；每处变更记录在变更记录 |
| `mcp` | 稳定（Tool Client 范围内）；协议范围扩张（resources 等）按次版本发布 |
| `internal/*` | 零承诺，随时变动 |

## 路线图

已完成：

- [x] 第一阶段：`message` `tool` `llm` `provider` `factory` `agent` `mcp`
- [x] `runtime` — 持久化运行：状态机、事件库、调用级检查点、恢复对账（孤儿结果复用 + RetryPolicy 分级 + 协议安全边界）、fail-closed、Stream 缺口补读
- [x] `rag` + `embedding` + `storage` — 分块/向量化/RRF/Pipeline/Retriever→Tool、SQLite 持久实现、`OpenRuntime` 开箱预设
- [x] 恢复边界加固：状态写入传错、终态提交顺序、审批等待期检查点、不确定调用持续阻断、故障注入回归测试

进行中 / 计划：

- [ ] **v0.2**：最小 Client 门面（`Config`/`Client`/`Run`，内部适配现有 runtime——详见[架构设计](embedded-integration-design.md)）；ModelBox、mdk 迁移
- [ ] **v0.2**：`retrieval/{vector,fulltext,hybrid}` + `rerank/{llm,score}` + `splitter/{text,markdown}` 拆包（当前策略在 rag 内）；FullTextStore 首个实现（SQLite FTS5）
- [ ] **v0.3**：统一 Error 码体系；Preset 体系与契约测试
- [ ] **v1.0 前评估**：多轮 RAG 查询改写（真实应用痛点驱动）
- [ ] `compose`（Graph / Workflow）——**等真实需求**，没有排期

## 明确不做

- 图编排 / 多智能体编排框架（那是 eino/langgraph 的战场）；
- 独立 HTTP AI 服务（库只做嵌入运行时）；
- 多实例分布式恢复（租约/执行权机制）——单进程模型，多实例需外部协调；
- 缓存所有会话历史 / 框架自带配置格式 / 依赖注入容器。

## 升级指南

各版本的破坏性变更与迁移步骤在发布时追加到[变更记录](_变更记录.md)对应版本小节。通用建议：

- 锁版本引用（`go get github.com/dingkui/dlz-goai@v0.x.y`）；
- 自定义 Provider/Store 的实现放应用侧并跑本库契约测试（`runtime/`、`storage/sqlite` 的测试即模板）；
- 依赖 `internal/*` 的代码升级必读变更记录。
