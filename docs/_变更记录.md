# 变更记录

本文件记录 dlz-goai 的用户可见变更，配合 [升级计划](升级计划.md) 使用。格式：版本 → 变更条目（Added / Changed / Fixed / Removed）。

## 未发布（feat/m1-reliability 分支，待合入 main 成为 v0.1.0）

### Added

- 根包 `dlzgoai`：**最小 Client 门面**——`NewClient`（装配模型/默认工具/存储并校验）、`Start`（后台执行，返回 `Run` 句柄；ctx 只控制提交，前端断开不取消运行）、`Resume`（检查点续跑，工具自动使用 Client 默认工具集）、`Wait`（ctx 取消只停止等待）、`Cancel`、`Approve`（审批跨 HTTP 解耦）、`GetRun`/`Subscribe`/`Replay`/`Stream`、`Close`（取消全部活跃运行并等待退出，不触碰应用注入的资源）、`ActiveRuns` 诊断
- `runtime`：持久化运行——状态机（pending/running/waiting_approval/succeeded/failed/canceled）、事件落库与单调 Seq、**三级检查点**（初始/调用级/步级）、`Resume` 恢复对账（孤儿结果复用不重执行；不确定调用按 `RetryPolicy` 持续阻断）、协议安全边界回退（trimDangling）、fail-closed（持久化失败中止运行并传错）、`Recover` 进程恢复
- `runtime`：`Stream(ctx, runID, afterSeq, emit)`——回放 + 实时 + Seq 缺口自动补读，慢消费者不丢事件；运行结束关闭订阅通道并最终补齐；`run_resumed` / `run_done` / `run_error` 终态事件
- `tool`：`RetryPolicy` 恢复分级接口（`RetrySafe` 默认 / `NeedsVerify` / `NoRetry`）
- `agent`：`OnToolDone` 钩子（调用级检查点挂点）；空工具集退化为普通对话
- `mcp`：`DefaultClientInfo()` + `Client.Info` / `StdioClient.Info` 可配置客户端标识
- `storage/sqlite`：`OpenRuntime(path)` 一行装配 runtime 三 Store 的开箱持久化预设
- CI：GitHub Actions（ubuntu + windows 矩阵，build / vet / test -race）
- 文档：README（四段式入口）、快速开始、使用手册七篇（llm/tool/agent/mcp/runtime/rag/storage）、实战案例（接入现有 Go 项目）、扩展手册五篇、升级计划

### Changed

- 错误消息全面转英文（sentinel 错误与模型可见回执文案）；`errors.Is` 用法不受影响
- `mcp` initialize 不再上报硬编码客户端名，改用可配置 `Info`（默认 `dlz-goai`）
- runtime 事件订阅通道在**运行结束时关闭**（此前仅 unsubscribe 时关闭）——依赖通道不关闭的代码需适配

### Fixed

- 状态登记写入失败被静默吞掉（表现为"返回成功但登记停在 running"）
- 终态事件（run_done）落库失败仍返回成功
- 首个工具等待审批前没有可恢复检查点（此时崩溃 Resume 必失败）
- 恢复对账误把"审批中断/被拒绝"等未执行回执当作可复用的执行结果
- `Resume` 从步中途检查点续跑产生悬空 tool_calls（部分模型服务会拒绝）
- `NoRetry` 工具的不确定调用只被拦截一次（模型重试即绕过）
- 并行工具并发命中恢复索引的数据竞争
- `Stream` 慢消费者丢事件且无法补齐、终态事件丢失导致永久等待

### 基线（此前已有的能力，v0.1.0 打包内容）

- `llm` / `provider/openai` / `provider/ollama` / `factory`：统一模型流式调用、多服务配置 Store、端点回退、用量统计
- `tool` / `message`：工具契约、类型化工具（Typed）、Registry、策略（auto/confirm/deny）
- `agent`：工具调用循环（步数上限/单工具超时/UTF-8 安全截断）、审批（Broker）、事件流、并行执行、步数用尽兜底总结、中断韧性
- `mcp`：stdio + Streamable HTTP 双传输、增量配置重建、工具命名空间、后台刷新
- `rag` / `embedding` / `storage`：分块、双厂商 Embedder、内存/SQLite VectorStore、RRF 融合、Pipeline、Retriever→Tool
