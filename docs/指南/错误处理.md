# 错误处理

本文描述当前 master 的实际行为。工具回执、模型调用错误、Client 提交错误和持久化错误需要分别处理。

## 工具失败不一定终止运行

| 来源 | 当前 Agent 行为 |
|---|---|
| 工具返回 `tool.Result{IsError: true}` | 发出 tool_error，写入模型可见的工具消息，循环可继续。 |
| 工具 Execute 返回 Go error | 转换为 tool_error 和模型可见回执，循环可继续，不会仅因这个 error 自动上抛终止。 |
| 参数非法、未知工具、策略拒绝 | 返回模型可见的错误回执。 |
| 模型调用返回 error / Delta.Error | 返回本轮错误；已产生的部分轨迹可从 Result 获取。 |
| 审批 Handler 返回 error | 中止当前调用及运行。 |
| Runtime 持久化失败 | 终止并返回错误；不能假设失败状态本身仍能写入故障中的 Store。 |

工具的错误文本会暴露给模型，应先去除凭据等敏感内容。业务若要求某类工具失败立即终止，需要在集成层明确实现该策略，不能依赖两种工具返回通道自动区分是否继续。

## Client 错误

| 错误 | 处理 |
|---|---|
| `dlzgoai.ErrNoModel` | 提供 Options.Model 或 Request.Model；ResumeWith 必须显式提供 Model。 |
| `dlzgoai.ErrNoInput` | 提供 Input 或非空 Messages。 |
| `dlzgoai.ErrClientClosed` | Client 已退出，不能继续 Start/Resume。 |
| `dlzgoai.ErrRunNotManaged` | Wait 目标不在当前 Client 内；历史运行用 GetRun/Replay。 |

Start 成功只表示创建后台运行句柄。模型、存储和 Resume 状态校验错误从 Wait 返回。等待超时与取消任务不同，详见 [Client](../使用手册/client.md)。

## Runtime 与审批错误

| 错误 | 处理 |
|---|---|
| `runtime.ErrRunNotFound` | 检查 ID 和 Store；Start 成功返回后登记已可查询。 |
| `runtime.ErrRunActive` | 同一运行仍在进行，继续查询或订阅，不重复 Resume。 |
| `runtime.ErrRunTerminal` | 成功运行不能 Resume；查结果或回放。 |
| `runtime.ErrNoCheckpoint` | 检查检查点是否存在；未配置 CheckpointStore 也会报错，但不一定是此 sentinel。 |
| `agent.ErrApprovalNotPending` | 当前调用没有待决审批；确认是否已经处理，或是否处于短暂注册窗口。 |
| `agent.ErrRunNotFound / ErrApprovalAborted` | 审批目标不存在、结束或等待已被中断。 |

配置片段：

```go
result, err := run.Wait(ctx)
switch {
case err == nil:
    // 使用 result.Content；业务操作是否成功仍应检查业务回执。
case errors.Is(err, context.DeadlineExceeded):
    // 只停止等待，可稍后继续 Wait；停止执行需 Cancel。
case errors.Is(err, runtime.ErrRunActive):
    // 不重复恢复，继续查询已有运行。
default:
    // 记录错误并向用户呈现；持久化失败时登记也可能滞后。
}
```

直接调用 Registry 或 Tool 时，可能得到 `tool.ErrNoHandler / ErrNotFound / ErrDuplicate / ErrInvalidArguments / ErrDenied`。经 Agent 调用的实际回执路径以上表为准。MCP 的 HTTP 错误可通过 `errors.As` 匹配 `*mcp.HTTPError`，具体类型见源码。

## 匹配与升级

使用 errors.Is/errors.As，不解析错误字符串。模型可见的回执文字不是稳定 API。当前没有统一 Error.Code；未来计划只在 [升级计划](../升级计划.md) 中维护，尚未实现的类型不要用于生产代码。
