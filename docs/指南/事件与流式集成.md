# 事件与流式集成

使用 Client 将任务执行与 HTTP 连接分开：开始端点只提交任务，事件端点跟随 Stream，审批和取消通过独立端点提交。本文代码为应用集成片段，Handler、鉴权与错误响应由宿主应用实现。

## 端点分工

| 端点示例 | Client 调用 | 职责 |
|---|---|---|
| POST /runs | Start | 校验输入和权限，返回 runID。 |
| GET /runs/{id} | GetRun | 查询状态及 PendingApproval。 |
| GET /runs/{id}/events?afterSeq=N | Stream | 补读历史并跟随进度，请求断开仅停止订阅。 |
| POST /runs/{id}/approvals | Approve | 验证当前用户及调用参数后提交明确决策。 |
| POST /runs/{id}/cancel | Cancel | 请求取消；随后查询最终状态。 |
| POST /runs/{id}/resume | Resume | 在业务确认后继续失败/取消的运行；后台错误用 Wait/GetRun 查询。 |

Start/Resume 在登记就绪后返回句柄，可立即查询和订阅。准备阶段失败直接返回错误，模型和工具执行错误由 Wait 返回。

## 事件消费

| 事件 | UI 用法 |
|---|---|
| run_start / run_resumed | 显示开始或继续。 |
| model_delta | 追加正文增量。 |
| tool_proposed / tool_started | 按 CallID 展示工具卡片。 |
| tool_result / tool_error | 展示回执；tool_error 不一定终止运行。 |
| approval_required | Approved 为 nil 时展示待审批；非 nil 时更新决策。 |
| final | 展示模型最终回答，尚不等于 Runtime 提交结束。 |
| run_done / run_error | 更新当前尝试的终态。 |

事件公共字段见 [agent.Event 源码](../../agent/event.go)。不要在文档另抄一份完整结构体，以免新增字段时失配。

## SSE 写入片段

该最小片段没有心跳 goroutine，所有 ResponseWriter 操作都在 Stream 的同步回调中完成。`h.client` 为共享 Client，`runID` 与 `afterSeq` 已经过校验及授权检查：

```go
flusher, ok := w.(http.Flusher)
if !ok {
    http.Error(w, "streaming unsupported", http.StatusInternalServerError)
    return
}
w.Header().Set("Content-Type", "text/event-stream")
w.Header().Set("Cache-Control", "no-cache")
ctx, stop := context.WithCancel(r.Context())
defer stop()
var writeErr error
err := h.client.Stream(ctx, runID, afterSeq, func(e agent.Event) {
    if writeErr != nil { return }
    data, marshalErr := json.Marshal(e)
    if marshalErr != nil { writeErr = marshalErr; stop(); return }
    _, writeErr = fmt.Fprintf(w, "id: %d\nevent: %s\ndata: %s\n\n", e.Seq, e.Type, data)
    if writeErr != nil { stop(); return }
    flusher.Flush()
})
if writeErr != nil {
    log.Printf("event delivery failed: %v", writeErr)
} else if err != nil && r.Context().Err() == nil {
    log.Printf("event stream failed: %v", err)
}
```

JSON 编码可避免正文换行破坏 SSE 帧。生产服务还应配置写入期限，避免慢连接长期阻塞。如果需要心跳，使用单个 writer goroutine 同时处理事件队列和 ticker；或让写入与 Flush 共用同一互斥锁，且在 Handler 返回前停止并等待心跳 goroutine。不要在锁外 Flush。

浏览器使用命名事件时需要 `addEventListener` 监听对应事件类型；重新连接可读取 Last-Event-ID，或显式传 afterSeq。按已消费的 Seq 去重，序号缺口交由 Stream 补读；不要把原始 Subscribe 当作完整事件流。

## 持久化与回放边界

配置 EventStore 时，Runtime 尝试先保存事件再转发；存储失败会返回错误。未配置 EventStore 时不存在落库保证。内存 EventStore 的记录仅存活于当前进程。

Replay 返回保存的原始历史；Stream 面向当前执行尝试，会跳过旧尝试终态并可能合成终态提示，因此不能承诺它与 Replay 逐条完全相同。审计以 Replay 为准。终态合成、补读和恢复行为目前为实验性，不作可靠性保证。

默认 Broker 在等待器注册后再发布审批状态和事件，收到事件即可提交。ErrApprovalNotPending 表示该调用当前没有待决审批，应刷新状态，不要重复批准。

## 应用负责的状态

- 认证、运行归属和工具授权由服务端校验，不能仅凭 runID 允许访问或批准。
- 待审批页通过 GetRun 重建，不能仅依赖收到过实时事件。
- 关闭页面只结束事件请求；明确点击停止才调用 Cancel。
- Stream 返回存储错误时展示中断并提供查询入口，不能伪造业务成功。
