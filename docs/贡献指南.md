# 贡献与文档维护

## 文档分工

- README 展示用途与推荐入口；快速开始提供能直接运行的程序。
- Client 手册解释接入契约，Agent/Runtime 手册解释底层行为。
- 工具错误只在错误处理指南集中定义，其余页面引用它。
- 架构草案与路线图记录规划，不作为当前 API 使用说明。
- 实验性恢复的示例与内部验证不构成可靠性保证。

## 检查文档

需要 PowerShell 7 与 Go 1.24+，在仓库根目录执行：

```bash
pwsh -File scripts/check-docs.ps1
```

脚本检查本地行内 Markdown 链接、代码围栏、所有 examples 包编译，以及 README/docs 内带 package main 的 Go 代码块编译；运行无需网络模型的 fullstack 演示。HTTP/模型服务不会启动或被调用。临时构建输出保存在系统临时目录。

片段不作为完整程序编译，必须标明缺少的应用上下文。主要教程应引用 examples 中的完整实现。远程链接、锚点、真实模型能力与真实进程故障恢复不在此检查范围。

## 库内 Provider 开发

internal/wire 的 Codec 供本仓库内部 Provider 复用 HTTP/SSE 实现，不是外部扩展 API。外部应用应实现公开 llm.Provider。若新增官方 Provider，应放在库内并为端点、工具分片、错误与取消行为补测试。

## 发布同步

发布标签后更新变更记录中的版本节，未来改动保留在“未发布”。示例或文档在标签之后更新时，说明适用的仓库版本。不要移动已发布标签来让文档看起来一致。
